Sensible Daten lokal verarbeiten — Cloud-KI nutzen ohne Datenleck

Ein Framework für Claude Code, das personenbezogene Daten ausschließlich auf deinem Rechner verarbeitet. Lokales LLM (Gemma) bleibt Wächter, Claude bekommt nur anonymisierte Aggregate.

Wieso überhaupt Claude? Wieso nicht alles lokal?

Berechtigte Frage. Die ehrliche Antwort: Spezialisierung. Lokale und Cloud-KI sind nicht gleich gut — sie sind in verschiedenen Dingen brillant.

🛡️ Was Gemma 4 lokal gut kann

~4 Milliarden Parameter, läuft auf 16 GB RAM. Optimiert für strukturierte Aufgaben.

  • ✓ Daten aus Dateien extrahieren
  • ✓ Felder filtern und anonymisieren
  • ✓ Personenbezüge erkennen
  • ✓ Einfache Texte aus Vorlagen befüllen
  • ✓ Aggregate berechnen (Durchschnitt, Anzahl)

☁️ Was Claude (Cloud) viel besser kann

~200+ Milliarden Parameter, riesige Trainingsbasis. Spezialisiert auf komplexe Aufgaben.

  • ✓ Strategisches Planen mit vielen Constraints
  • ✓ Kreatives Schreiben (Briefe, Anträge, Berichte)
  • ✓ Strukturiertes Reasoning über komplexe Sachverhalte
  • ✓ Code-Generierung und Refactoring
  • ✓ Domänenwissen (Recht, Pädagogik, Verwaltung)

💡 Die Analogie

Gemma ist wie ein Anwaltsgehilfe: kennt die Akten, sortiert, schwärzt sensible Stellen, fasst zusammen.
Claude ist wie ein spezialisierter Anwalt: bekommt die geschwärzten Akten und schreibt darauf basierend strategisch durchdachte Plädoyers.

Niemand würde sagen "schick einfach den Anwaltsgehilfen vor Gericht" — beide haben ihre Rolle. Die Cloud-KI ist nicht ersetzbar bei strategischen Aufgaben. Aber sie braucht keinen Zugriff auf identifizierende Daten, um diese Aufgaben zu lösen.

Konkretes Beispiel: Wintersportwoche

Gemma macht:

Schülerdaten lesen → anonymisieren → Eltern-Brief mit Vorlage befüllen → Notfall-Liste ausdrucken

Claude macht:

Optimale Gruppeneinteilung mit Niveau- und Größen-Constraints, Brief-Vorlagen formulieren, komplette Förderanträge mit Begründung schreiben

Zwei Ansätze, ein Ziel

Das Framework bietet zwei Strategien, je nach Aufgabe und Datensensibilität.

🛡️ Delegation an Gemma

Claude weiß: "Da liegen sensible Daten, die ich nicht sehen darf." Es ruft Gemma als Tool auf — Gemma liest die Datei lokal, verarbeitet sie und gibt nur Aggregate zurück.

  • Sensible Datei nie in Cloud
  • Aggregate (Durchschnitt, Anzahl) sind sicher
  • Klare Audit-Spur
  • Permission-System verhindert Bypass

🔄 Pseudonymisierung

Wenn Claude doch mit Personen-Kontext arbeiten muss: Lokales Mapping ersetzt Namen durch Tokens wie [PERS_a3f2]. Claude arbeitet damit, lokal wird zurückübersetzt.

  • Klarnamen bleiben lokal
  • Claude versteht Person-Kontext
  • Reversibel über lokale Lookup-Tabelle
  • Leak-Detector als Sicherheitsnetz

Was das Framework liefert

Ein MCP-Server für Claude Code mit sechs Tools.

🔍

gemma_query

Lässt das lokale LLM eine Datei verarbeiten und gibt nur das anonymisierte Ergebnis an Claude zurück.

🎭

pseudonymize

Ersetzt echte Namen, E-Mails, Telefonnummern durch stabile Tokens. Lokale Lookup-Tabelle.

🔓

depseudonymize

Wandelt Tokens zurück in Klartext. Claude liefert Pseudo-Antwort, du siehst echte Namen.

📋

show_mappings

Zeigt die aktuelle Zuordnungstabelle: welcher echte Wert wurde welchem Token zugewiesen.

📜

show_audit_log

Vollständiges Audit-Log aller Verarbeitungen — DSGVO Art. 30 konform.

⚙️

system_status

Status der lokalen Ollama-Installation und verfügbarer Modelle.

🤔 Was, wenn meine Schule nur alte Geräte hat?

Auf einem Windows-PC mit 8 GB RAM und Intel-Prozessor läuft gemma:2b — langsamer (eine Wintersportwoche-Aufgabe dauert dann eher 2-3 Minuten statt 30 Sekunden), aber funktioniert. Für gelegentliche Nutzung absolut akzeptabel.

Empfehlung für Schulen ohne moderne Hardware: Ein einzelner Verwaltungs-PC mit 16 GB RAM (~€800 Anschaffung) reicht für die ganze Schule — das Modell läuft auf einem Rechner, Claude Code wird darauf bedient.

Häufige Fragen

Ehrliche Antworten auf typische Skeptiker-Fragen.

🛡️ Datenschutz & Sicherheit
Wie sicher ist das wirklich? Was sieht Anthropic von meinen Daten?

Anthropic sieht nur das, was die Cloud-API als Input bekommt. Wenn du das Framework nutzt, ist das per Definition die anonymisierte Version — also Geschlecht, Aggregate, Tokens wie [PERS_a3f2]. Niemals Klarnamen, Adressen, Allergien oder Telefonnummern.

Wichtig: Anthropic nutzt API-Inhalte standardmäßig nicht zum Training (laut Privacy Policy). Trotzdem ist die Faustregel: gehe davon aus, dass alles, was die Cloud erreicht, theoretisch protokolliert werden könnte. Genau deshalb gibt's dieses Framework — damit nichts Sensibles erst gar nicht in die Cloud kommt.

Ist das DSGVO-konform? Habe ich damit einen Bescheid in der Tasche?

Das Framework ist DSGVO-konform konstruiert ("Privacy by Design", DSGVO Art. 25). Es unterstützt zentrale Anforderungen:

Art. 5 Datenminimierung · Art. 25 Datenschutz durch Technikgestaltung · Art. 30 Verarbeitungsverzeichnis (Audit-Log) · Art. 32 Sicherheit der Verarbeitung · Art. 17 Recht auf Löschung

Aber: "DSGVO-konformes Tool" ≠ "Bescheid". Du brauchst trotzdem eigene Datenschutz-Folgenabschätzung, Verarbeitungsverzeichnis, ggf. Einwilligungen. Das Framework macht den technischen Teil — die organisatorischen Pflichten bleiben bei dir bzw. dem Datenschutzbeauftragten.

Was passiert, wenn jemand die Lookup-Tabelle auf meinem Rechner findet?

Die Lookup-Tabelle (Zuordnung Token → Klarname) liegt unter ~/.private-ai-bridge/lookup.json. Bei physischem Zugriff auf deinen entsperrten Rechner kann sie gelesen werden — wie jede andere Datei.

Schutzmaßnahmen: Festplattenverschlüsselung (FileVault auf Mac, BitLocker auf Windows, LUKS auf Linux) ist sowieso Pflicht für Geräte mit personenbezogenen Daten. Damit ist die Lookup-Tabelle bei verlorenen/gestohlenen Geräten sicher.

Optional: clear_mappings() löscht alle Zuordnungen, wenn sie nicht mehr gebraucht werden (Recht auf Löschung, DSGVO Art. 17).

Wie kann ich überprüfen, dass wirklich nichts Sensibles rausgeht?

Drei Mechanismen:

1. Audit-Log — jede Tool-Verwendung wird in ~/.private-ai-bridge/audit.log protokolliert (Zeitstempel, Tool, Datenkategorien). Lesbar mit show_audit_log.

2. Leak-Detector — Gemmas Output wird vor Übergabe an Claude gegen die Lookup-Tabelle geprüft. Findet er einen bekannten Klarnamen, blockiert er die Übertragung.

3. Open Source — der gesamte Code ist auf GitHub einsehbar. Du kannst (oder dein IT-Audit) den Datenfluss exakt nachvollziehen.

⚙️ Technik
Brauche ich einen API-Account bei Anthropic?

Nein. Das Framework läuft mit Claude Code — und das ist im Claude-Pro-Abo ($20/Mo) bzw. Claude-Max-Abo enthalten. Kein separater API-Account, keine API-Credits, keine unvorhersehbaren Rechnungen.

Für Schulen besonders relevant: kalkulierbare Fixkosten. Ein Max-5×-Abo ($100/Mo) reicht für intensive Nutzung durch eine Verwaltungsstelle.

Funktioniert das auch mit anderen LLMs als Gemma? (Llama, Mistral, ...)

Ja — solange das Modell über Ollama verfügbar ist. Setze einfach eine Umgebungsvariable:

export PRIVATE_AI_BRIDGE_MODEL="llama3.2:3b"

Empfohlene Alternativen: llama3.2:3b, mistral:7b, qwen2.5:7b, phi3:mini. Gemma 4 ist die aktuelle Empfehlung wegen guter Balance aus Qualität, Geschwindigkeit und RAM-Bedarf.

Was passiert ohne Internet?

Die lokale Komponente (Gemma) funktioniert komplett offline — du kannst sensible Daten lokal verarbeiten, anonymisieren, Notfall-Datenblätter generieren etc.

Die Cloud-Komponente (Claude) braucht naturgemäß Internet. Bei Internetausfall steht dir die volle lokale Funktionalität zur Verfügung — nur die kreativ-strategischen Aufgaben sind dann nicht möglich.

Wie aktualisiere ich das System?

Für Code-Updates: cd private_ai_bridge && git pull. Für neue Modellversionen: ollama pull gemma4:e4b.

Beides ändert nichts an deiner lokalen Lookup-Tabelle oder deinen Daten — die liegen separat in ~/.private-ai-bridge/.

📋 Praxis
Können mehrere Personen gleichzeitig damit arbeiten?

In der aktuellen Version: nein. Das Framework ist für Single-User-Nutzung gedacht — typisch ein Verwaltungs-PC mit dem Direktor / Sekretariat als Nutzer.

Für Multi-User-Setups (mehrere Lehrkräfte gleichzeitig) wäre eine zentrale Server-Installation nötig — das ist im aktuellen Framework nicht vorgesehen, aber technisch möglich. Pull Requests willkommen.

Wie sichere ich die Lookup-Tabelle (Backup)?

Die Lookup-Tabelle ist eine einfache JSON-Datei unter ~/.private-ai-bridge/lookup.json. Standard-Backup-Mechanismen funktionieren:

macOS: Time Machine sichert sie automatisch mit. Linux: rsync, Borg, restic. Windows: File History.

Wichtig: das Backup-Medium ebenfalls verschlüsseln — die Lookup-Tabelle enthält Klarnamen!

Kann ich Claude auch für Aufgaben nutzen, bei denen gar keine Personendaten dabei sind?

Selbstverständlich — Claude Code funktioniert ja unabhängig vom Framework genauso wie immer. Ohne sensible Daten ruft es einfach das gemma_query-Tool nicht auf, sondern arbeitet direkt.

Beispiele: Förderanträge ohne Personenbezug, allgemeine Recherche, Code für die Schulwebsite, Konzepte erarbeiten, Berichte aus Statistiken etc.

Wer haftet, wenn doch was schiefgeht?

Das Framework ist Open Source unter MIT-Lizenz und wird "wie besehen" zur Verfügung gestellt — ohne Gewährleistung. Das ist Standard bei Open Source und auch bei kommerzieller Software (siehe AGB).

In der Praxis bedeutet das: Verantwortlich für DSGVO-konformen Einsatz ist die Schule bzw. der Schulträger. Das Framework ist ein Werkzeug, das den technischen Teil sehr stark erleichtert — aber organisatorisch musst du den Einsatz korrekt aufsetzen (Verarbeitungsverzeichnis, ggf. DSFA, Schulung des Personals).

Empfehlung: vor produktivem Einsatz mit dem zuständigen Datenschutzbeauftragten abstimmen.
